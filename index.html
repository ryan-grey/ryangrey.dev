This Website

Static site served entirely from AWS — the site is its own case study.

Registered domain transferred from GoDaddy to Route 53 (including tearing down a stale DNSSEC chain — DS records deleted at the .dev registry before the nameserver cutover, so resolution never broke). Hosted from S3, fronted by CloudFront with a free ACM certificate. The .dev TLD is HSTS-preloaded, so every connection is HTTPS by force.

  • Keyless CI/CD — OIDC-federated deploys, no stored credentials; every deploy verified byte-for-byte against the commit, behind three drift guards that run before any credential is assumed
  • Security headers at the edge — a path-branched CSP: script-src 'none' on this page, which carries no JavaScript at all, and a separate narrow policy for the chatbot route
  • Self-testing monitoring — alarm → SNS → Lambda → SES, with a monthly heartbeat that shares no failure modes with the path it tests

Retrieval-Augmented Chatbot on Amazon Bedrock

Ask the assistant a question →

A RAG chatbot grounded in a corpus built from this site and the CV, so it answers from source text instead of hallucinating from general knowledge. Built alongside the AWS AI Practitioner track to understand the retrieval pipeline from the inside — chunking, embedding, and grounding — rather than treating the model as a black box.

  • No vector database — the corpus is embedded with Titan v2 and cosine similarity runs inside the Lambda; a managed vector store at this scale is cost without benefit
  • Answers cite their sources — the model sees only the retrieved chunks and is told to say it doesn't know rather than fill the gap
  • Bounded by design — a public LLM endpoint is an unbounded bill, so per-IP and global caps in DynamoDB fail closed, and the visitor's question is passed to the model as data, never as instructions
